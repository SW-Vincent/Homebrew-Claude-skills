# Google Tag Manager (GTM): client code and interface export

Contents: 1. Recognise the source, 2. Client code (gtm.js), 3. Interface export, 4. Correspondence
between the two, 5. Functions and tag types, 6. Identify the vendor, 7. Consent Mode and consent.

Anonymised examples (same container, two forms): `examples/gtm_client_code_example.js` and
`examples/gtm_interface_export_example.json`.

## 1. Recognise the source

| What you are looking at | Source |
|---|---|
| JS starting with `// Copyright 2012 Google Inc.` then `var data = {"resource": {...}}` | client code (gtm.js) |
| JSON with `exportFormatVersion` and `containerVersion` | interface export |
| JSON with `tag`, `trigger`, `variable` at the root, no envelope | version export through the GTM API (same content as the interface export) |

The link between the two: `resource.version` in the client code equals `containerVersionId` in the
export. If both files are provided, first check that the version is the same, otherwise the
differences you find are not anomalies but two versions.

## 2. Client code (gtm.js)

File fetched from `https://www.googletagmanager.com/gtm.js?id=GTM-XXXXXXX`, typically 250 to
500 KB. Useful object: `data.resource`.

```
data = {
  "resource": { "version", "macros": [...], "tags": [...], "predicates": [...], "rules": [...] },
  "runtime", "entities", "blob", "permissions", "sandboxed_scripts", "security_groups"
}
```

**What is lost compared to the interface**: names (tags, triggers, variables), folders,
descriptions. Triggers no longer exist as objects: they are dissolved into `predicates` and
`rules`. What is kept: the tag ID (`tag_id`), identical to the one shown in the interface.

### macros = variables
0-indexed array. Each entry has a `function` and `vtp_*` parameters. Tags, predicates and other
macros refer to them by position: `["macro", N]`.

| function | GTM variable | What it reads |
|---|---|---|
| `__v` | Data Layer Variable | `vtp_name` = path in the dataLayer |
| `__u` | URL | `vtp_component`: HOST, PATH, QUERY, URL... |
| `__f` | Referrer | component of the referring URL |
| `__e` | Event name | current dataLayer event |
| `__c` | Constant | fixed value |
| `__k` | 1st party cookie | `vtp_name` = cookie name |
| `__d` | DOM element | CSS selector or ID |
| `__jsm` | Custom JavaScript | JS function, to read to understand the logic |
| `__smm` | Lookup table | maps an input value to an output |
| `__remm` | RegEx table | maps by regular expression (often used to derive granted/denied from a CMP cookie) |
| `__aev` | Auto-event variable | attribute of the clicked element, target URL... |
| `__awec` | Google Ads, Enhanced Conversions | builds the payload (email, etc.) |
| `__cvt_<account>_<id>` | Custom template variable | read in `permissions` and `runtime` |

### tags
0-indexed array in file order, **different from the order of `tag_id`**. Note both. Keys of a tag:
`function`, `tag_id`, `vtp_*` (parameters), `once_per_event` or `once_per_load` (equivalent of
"Once per event / per page"), `priority`, `metadata`.

**Infrastructure tags** (generated by GTM to make triggers work, absent from the interface
export): `__tg` (trigger group), `__hl` (history listener), `__lcl` (link click listener), `__cl`
(click listener). Other prefixes of the same kind to know: `__fsl` (forms), `__sdl` (scroll),
`__tl` (timer), `__evl` (element visibility), `__ytl` (YouTube). On a real container they made up
nearly half of the tags in the file (23 out of 48). **Do not count them in the inventory**:
otherwise the total differs from the interface export of the same container. Mention their number
in the source limits.

### predicates = condition atoms
`{"function": "_op", "arg0": ["macro", N], "arg1": "value"}`.

| function | Meaning |
|---|---|
| `_eq` | equals |
| `_cn` | contains |
| `_sw` / `_ew` | starts with / ends with |
| `_re` | matches a regex |
| `_lt` `_le` `_gt` `_ge` | numeric comparisons |
| `_css` | matches a CSS selector |
| `_um` | URL match |

### rules = predicates to tags
A rule is a **list of clauses**, each of the form `["keyword", index...]`:

```json
[["if", 0, 1], ["add", 3, 9]]
[["if", 17], ["unless", 16], ["block", 0]]
[["if", 14, 35], ["add", 2], ["block", 1]]
```

- `if`: indexes of `predicates` that must ALL be true (AND).
- `unless`: separate clause (not mixed into `if`). The rule applies only if NONE of these predicates
  is true. It is the equivalent of a "not" filter in a trigger.
- `add`: the tags (indexes in `tags`) that fire when the rule applies.
- `block`: the tags that are prevented from firing when the rule applies.
- A single rule can contain both `add` and `block` (it adds one tag and blocks another).
- **Blocking always wins over adding** for the same tag.
- A tag present in several `add` rules has triggers combined with OR.

Reading a typical consent block: `[["if", 17], ["unless", 16], ["block", 0]]` with predicate 17
"event matches `.*`" (any event) and predicate 16 "CMP cookie contains `marketing:true`" means
"block tag 0 on any event, unless the cookie contains marketing:true", so the tag is blocked as long
as marketing consent is not there.

### Other sections
- `permissions`: per function name, the allowed domains (`inject_script.urls`), cookies read
  (`get_cookies`), global variables accessed (`access_globals.keys`). Basis for identifying the
  vendor of a custom template.
- `runtime`: sandboxed code of the templates (hard-coded strings, domains).
- `security_groups`: which functions are "customScripts" (`__html`, `__jsm`) and which are Google's.

### Paused tags in the client code
A tag paused in the interface appears as `__paused`, with only `vtp_originalTagType` (original
type). Its configuration is lost: the audit can only list its existence, ID and original type.
Behaviour described from an earlier case, not present in the September 2026 examples.

## 3. Interface export

```
{ "exportFormatVersion", "exportTime",
  "containerVersion": { "path", "accountId", "containerId", "containerVersionId", "name",
      "container": { "publicId": "GTM-XXXXXXX", "name", "usageContext", ... },
      "tag": [...], "trigger": [...], "variable": [...], "builtInVariable": [...],
      "customTemplate": [...], "fingerprint", "tagManagerUrl" } }
```

### tag
`tagId` (string), `name`, `type` (e.g. `html`, `googtag`, `gaawe`, `awct`, `gclidw`, `cvt_<id>`),
`parameter[]` (objects `{type, key, value}`, types TEMPLATE, BOOLEAN, INTEGER, LIST, MAP),
`firingTriggerId[]`, `blockingTriggerId[]` (lists of trigger IDs), `tagFiringOption`
(`ONCE_PER_EVENT`, `ONCE_PER_LOAD`, `UNLIMITED`), `priority`, `paused` (present and true if the
tag is paused), `consentSettings.consentStatus`, `monitoringMetadata`.

A paused tag **keeps its whole configuration** in the interface export: unlike the client code,
you can say what it was sending.

`consentSettings.consentStatus`: `NOT_SET` = no native consent setting on this tag. On the real
container analysed, all 25 tags were `NOT_SET` (blocking was done by home-made triggers). The
other values (`NEEDED`, `NOT_NEEDED`, with the list of consent types) were not observed: if you
meet them, note them as native per-tag consent.

### trigger
`triggerId`, `name`, `type`, `filter[]`, `customEventFilter[]`. Types met: `PAGEVIEW`,
`DOM_READY`, `CONSENT_INIT`, `CUSTOM_EVENT`, `LINK_CLICK`, `CLICK`, `HISTORY_CHANGE`,
`TRIGGER_GROUP` (the IDs of the member triggers are in `parameter` → `triggerIds`, all must
occur).

A filter = `{type, parameter[]}` with `arg0` (often a `{{Name}}` variable), `arg1` (value) and
sometimes `negate: true` (the filter is inverted). Operators met: `EQUALS`, `CONTAINS`,
`MATCH_REGEX`, `ENDS_WITH`. A `CUSTOM_EVENT` trigger fires if `customEventFilter` (event name) AND
all its `filter` entries are true.

**A trigger used as a blocker is an ordinary trigger**: nothing in its object says it blocks, it is
the tag that references it in `blockingTriggerId`. For a consent block, look for triggers named
"consent not granted" or equivalent, with a `negate` filter.

### customTemplate
List of the custom templates of the container: `templateId`, `name` (readable name, for example
"Meta Pixel"), `galleryReference` (origin repository), `templateData` (template code, including the
`___WEB_PERMISSIONS___` section). **This is the most direct way to name the vendor of a
`cvt_<id>` tag**: `type = cvt_<templateId>` matches the template whose `templateId` is `<id>`.

## 4. Correspondence client code / export

| Interface export | Client code |
|---|---|
| `tagId` | `tag_id` (identical) |
| `type: html` / `googtag` / `gaawe` / `cvt_XXXX` | `function: __html` / `__googtag` / `__gaawe` / `__cvt_XXXX` |
| `parameter[key=value]` | `vtp_<key>` |
| `firingTriggerId` | `add` clause of the rules |
| `blockingTriggerId` | `block` clause of the rules |
| filter with `negate: true` | predicate placed in `unless` |
| `tagFiringOption: ONCE_PER_LOAD` / `ONCE_PER_EVENT` | `once_per_load` / `once_per_event` |
| `paused: true` | `function: __paused` (configuration lost) |
| `name` of the tag, trigger, variable | absent |
| trigger type | deduced from the event tested: `gtm.js` (page view), `gtm.dom` (DOM ready), `gtm.load` (window loaded), `gtm.init_consent` (consent initialization), `gtm.click`, `gtm.linkClick`, `gtm.historyChange`, or a dataLayer event |
| infrastructure tags `__tg`, `__hl`, `__lcl`, `__cl` | absent |

Useful check: on the same container, tag IDs and the set of blocked tags must be identical in both
sources once infrastructure tags are excluded.

## 5. Functions and tag types

| Client code / export | GTM tag | Typical category |
|---|---|---|
| `__html` / `html` | Custom HTML | to determine: read the JS or pixel included |
| `__googtag` / `googtag` | Google tag | depends on the ID prefix, see below |
| `__gaawe` / `gaawe` | GA4 event | Google Analytics 4 |
| `__gaawc` / `gaawc` | GA4 configuration (older form) | Google Analytics 4 |
| `__awct` / `awct` | Google Ads, conversion tracking | Google Ads |
| `__sp` / `sp` | Google Ads, remarketing | Google Ads |
| `__gclidw` / `gclidw` | Conversion Linker | Google Ads infrastructure |
| `__flc` `__fls` | Floodlight counter / sales | Display, Campaign Manager 360 |
| `__ua` / `ua` | Universal Analytics | obsolete since July 2023 |
| `__paused` | paused tag | original type only |
| `__cvt_<id>` / `cvt_<id>` | custom template | to determine, see section 6 |

ID prefixes of a `googtag` (parameter `tagId` / `vtp_tagId`):

| Prefix | Product |
|---|---|
| `G-` | Google Analytics 4 |
| `AW-` | Google Ads |
| `DC-` / `GT-` | Campaign Manager 360, Display & Video 360 (Floodlight via gtag) |
| `GTM-` | another GTM container |

No `G-` in the whole container means there is no GA4. A `__gas` variable (Google Analytics
Settings) that no `__ua` tag references any more is a dead leftover, not GA4.

## 6. Identify the vendor of a custom template

The function name never gives the vendor. In order of reliability:

1. **Interface export**: `customTemplate[].name` and `galleryReference`.
2. **Client code**: the `permissions` section, per function (`inject_script.urls`, `get_cookies`,
   `access_globals`). The `extract_container.py` script surfaces it in the `permissions` field of
   each tag.
3. Tag parameters: `pixelId`, `partnerId`, `merchantId`, `advertiserId` indicate the type of
   platform.
4. Hard-coded strings in `runtime`.
5. Otherwise: write "vendor to confirm" rather than guessing.

## 7. Consent Mode and consent

The verdict concerns Google tags (Ads, GA4, Floodlight...). Detail it per product if the situation
is not uniform (the "Mixed" case).

**Principle: Consent Mode is very often driven by the cookie banner (CMP), not by the tag
manager.** What the container does not show therefore does not prove that it does not exist. Any
verdict based on the container alone that falls under section 7.2 carries an **asterisk** and the
alert "to confirm with a real test" (7.3).

### 7.1 The signals are in the container (the tag manager handles Consent Mode)

Signs: tags that call `gtag('consent','default', ...)` then `gtag('consent','update', ...)`
(Custom HTML, or a CMP template such as OneTrust, Didomi, Axeptio). Note `ad_storage`,
`analytics_storage`, `ad_user_data`, `ad_personalization`, `wait_for_update`, `url_passthrough`,
`ads_data_redaction`. Then check whether the Google tags are subject to consent, through a native
setting (`consentSettings` in the export; in the client code, a non-`vtp_` key in `other_keys` of
the script output) or through a trigger or blocker condition that reads the CMP cookie (more
fragile, to flag). Verdict, per product:

- **Basic**: signals present AND Google tags not fired before consent.
- **Advanced**: signals present AND Google tags fired without any consent condition (Google adapts
  the behaviour on its side).
- **Mixed**: different verdicts depending on the product. Write it tag by tag.

Always cite the tags and the precise condition that justify the verdict.

### 7.2 No signal in the container (Consent Mode is perhaps handled by the CMP)

**Never** conclude "Consent Mode not implemented". Two scenarios, told apart by whether the Google
tags are subject to consent in the container or not:

| Finding in the container | Possible readings, indistinguishable without a test |
|---|---|
| **Google tags not subject to consent** | (1) **consent management defect**; or (2) **Consent Mode Basic** handled by the CMP, which prevents GTM or the Google scripts from loading until consent is given |
| **Google tags subject to consent** (native setting, or trigger or blocker condition reading the CMP) | (1) consent handled **"the old way"** (tag blocking, without Consent Mode); or (2) **Consent Mode Advanced** (Consent Mode driven by the CMP + consent) |

To write in the report, with the asterisk, for example:
"Google tags not subject to consent in the container, no Consent Mode signal: consent management
defect or Consent Mode Basic handled by the CMP*."
"Google tags subject to consent, no Consent Mode signal: consent handled the old way or Consent
Mode Advanced handled by the CMP*."

### 7.3 What settles it: a real test

The container alone does not allow a choice. In the browser's Network tab, on a fresh session,
**before any choice in the banner**:
- Do GTM (`gtm.js`) and the Google requests go out? No call before the choice points towards Basic
  or an old-style block; calls from page load are either a management defect or Advanced.
- What is the value of the `gcs` parameter of the measurement requests? `G100` indicates denied
  signals (ad and analytics), `G111` granted signals: requests with `G100` before the choice
  indicate Advanced.
Repeat the measurement after a refusal, then after an acceptance.

### 7.4 Case where even 7.1 becomes not determinable

**Server-side**: a server container or first-party collection (transport_url, dedicated collection
domain) can apply its own filters, invisible here. Write "not determinable from the client
container, server implementation detected*".
